# Project and source storage

`ProjectStore` persists project heads, immutable snapshots, source metadata and coverage under its configured `rootDir`; original bytes are content-addressed under `objects/`, with run state in `runs/`. Construct it with `new ProjectStore({rootDir})`. Its public operations are asynchronous. `getSnapshot(projectId, snapshotId?)` returns a cloned effective view with inherited content resolved. A requested snapshot must belong to that project. Forks pin a specific parent snapshot, so later parent edits do not mutate a child's view; an explicit rebase creates a new child snapshot.

`commit(projectId, expectedSnapshotId, changeSet)` performs an optimistic head check under both the in-process queue and a cross-process kernel lock, writes an immutable snapshot, then atomically replaces the small project head file. Concurrent writers with the same expected head have one winner; others receive `SNAPSHOT_CONFLICT`. The head replacement is atomic for process-level readers, but files/directories are not explicitly fsynced, so power-loss durability is not guaranteed. Returned API values are clones; editing them cannot mutate stored snapshots.

Source registration preserves input bytes, computes a SHA-256 digest and records extracted regions and reader coverage. `readSource(sourceVersionId)` accepts an opaque version ID, never a path, and can reopen historical source bytes after updates. It verifies the digest before returning a `Buffer`. `openSourceRegion` resolves a region from a pinned snapshot and enforces the selected source scope.

Procedure definitions are immutable by exact `id@version`. The initial version may be active. A later version is an inactive draft and leaves the prior version active. `approveProcedure(projectId, expectedSnapshotId, {id,version,reviewedBy})` activates only the pinned unreviewed draft, records manager approval metadata, and deactivates the prior version. Source and procedure updates stale dependent findings transitively; rebase also marks local findings stale when their pinned inherited source/procedure versions changed. Fork-pinned snapshots remain stable until rebase.

Entity reconciliation uses a trusted operation journal: `reconcileEntities` accepts identity IDs rather than replacement records; `undoEntityReconciliation` accepts the server-owned operation ID, never client-supplied inverse data. Both commit against an expected head and invalidate dependent assessments. Process locking and optimistic checks apply to these operations too.

Text readers preserve stable line/page/row locators. Plain-text line offsets use UTF-16 code units in the original decoded string, including CRLF/CR terminators in coordinate calculations; each text locator declares `offsetUnit: "utf16-code-unit"`, and line text must equal `sourceText.slice(start,end)`. The original source bytes remain addressable by digest. Plain-text Project Gutenberg sources with explicit START/END EBOOK markers annotate every region as front matter, work, or back matter while retaining those original offsets and source bytes. CSV and TSV retain delimiter semantics and cell coordinates. PDF uses bounded asynchronous Poppler extraction and page rendering with Tesseract OCR when installed; unreadable and blank pages keep explicit page coverage entries. EPUB follows its OPF spine under aggregate byte, entry and deadline bounds; deferred chapters are recorded. OCR regions identify their page and extraction profile and carry a fidelity caveat. DOCX extraction can omit tables and non-body structures; unsupported files are retained with unreadable coverage rather than fabricated text.

The query index is keyed by snapshot ID and content fingerprint. It persists lexical BM25 documents and structural predicate/entity/argument postings. Every lookup filters to the requested source scope before ranking and returns region locators that can be reopened under that same pinned snapshot.
