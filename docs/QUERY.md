# Scoped retrieval and semantic resolution

`searchSources({snapshot,query,sourceScope,topK,rootDir})` performs lexical BM25 retrieval over a pinned source view. It computes document statistics after filtering to `sourceScope`, so a large out-of-scope source cannot skew ranking. Results include the exact `sourceVersionId`, `regionId`, quote, locator and reader-fidelity caveat. `openSourceRegion({snapshot,sourceVersionId,regionId,sourceScope})` reopens the cited region and rejects out-of-scope IDs.

`queryKnowledge({snapshot,goal,sourceScope,options,rootDir})` uses a persisted snapshot-fingerprinted structural index to select predicate candidates, then applies the deterministic SKE matcher. It is exact structural matching, not fuzzy entailment. Matches preserve bindings, evidence IDs, qualifiers and contested/ambiguous state. Stale records are excluded by the semantic matcher; source-scope closure is applied before use.

`resolveSemantics({question,goal?,scope?,snapshot,sourceScope,session,checkpointDir,signal,onEvent,procedures?,maxIterations?,maxHits?,rootDir?})` adds a bounded Luna interpretation and retrieval loop. It records a persistent agenda, binding rows and unresolved residuals; calls the lexical index after structural misses; asks Luna for exact source-quoted candidate propositions and useful subgoals; and independently reviews each candidate using ingestion receipts. It returns `{answerPackage,evidence,ephemeralRecords,reviewReceipts,ledger,checkpoint,cost,validation}`. `ephemeralRecords` are worker-local candidates, never a publication changeset. Only a caller that validates their bound review receipts against the same pinned snapshot and source scope may use them in an audit view. The final status is computed from structural matching of the root goal; a matched subgoal by itself cannot prove the root answer.

The loop caps its iterations and retrieved passages, persists its checkpoint only for the exact snapshot/scope/question/goal/procedure fingerprint, and resets an interrupted running agenda item to pending on resume. `cost` reports measured query-turn token counters when supplied by the session, model request count, wall time, and prompt characters. No embeddings, neural reranker, or expert judgment are implied by these APIs.
