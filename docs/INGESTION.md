# Whole-source ingestion and review

`ingestProject({snapshot,sourceScope,session,checkpointDir,signal,onEvent,procedures})` uses the shared persistent `CodexLunaSession` (pinned to `gpt-6-luna`). It chunks original reader regions without changing region identity, extracts only proposed source claims, repairs malformed SKE/quotes in a separate bounded turn, then sends candidates through an independent semantic-review turn. Accepted records retain source version, region, exact quote, locator, qualifiers, stable entity IDs, model/session review metadata and a fingerprint-bound review receipt. This is model review, not human approval.

Every readable source region has an extraction ledger entry. Unreadable pages/chapters and deferred reader regions remain visible as coverage gaps. Rejected non-entailed candidates are distinct from parser/review failures; incomplete review remains partial and can be retried with `retryIngestionChunk({checkpointDir,sourceVersionId,chunkId,expectedFingerprint})`. A retry reopens only that named chunk and requires the exact checkpoint fingerprint. A checkpoint is pinned to snapshot, exact source digests/profiles, policy and procedure versions; it cannot silently resume against a changed project state. Re-ingestion is idempotent for semantically identical record IDs. The exact-fingerprint retry path is covered by a transient-failure/resume regression.

`reviewAssertions({candidates,snapshot,sourceScope,session,signal,onEvent})` is also usable for ephemeral question-time source interpretations. It returns `{records,receipts,rejected,...}`; the caller must validate receipts against the pinned snapshot before using these records in a private audit view. They are not committed by this function.

`materializeProcedures({snapshot,procedureIds:[{id,version}],parameters,sourceScope,session,signal,onEvent})` requires exact active versions. It supplies full in-scope raw passages, including regions without accepted SKE facts, and separately accepted structured assertions to each procedure review. Procedures echo an exact server-issued chunk ID and explicitly list unreviewed region IDs; the server accounts for every actually supplied region and does not trust a model's aggregate count. Findings are procedural assessments rather than source facts; support and counterevidence IDs, source-version dependencies, procedure version, model-review receipt and per-region coverage are recorded. Partial source or procedure coverage creates named residuals. A detected Project Gutenberg START/END boundary can restrict these procedures to the complete marked work; front matter and legal back matter remain source-addressable and are recorded as intentionally excluded. A source/procedure change invalidates dependent findings; rerun the selected active version to recompute.

Entity identity decisions are batch-reviewed with provisional IDs so same-character mentions can join within one extraction batch while same-name entities stay separate absent evidence. The reviewer also receives the cited line plus its immediate preceding/following source regions for local pronoun, fragment, attribution, world, and counterevidence context; those neighbors are marked context-only and do not expand the quote citation or allow a claim that needs missing neighboring text to be promoted. Authorized owners can merge identities with `ProjectStore.reconcileEntities` and reverse the exact journaled operation with `undoEntityReconciliation`; both operations use expected-snapshot concurrency checks and invalidate dependent findings.

The context pass compares accepted assertions in bounded batches (at most 100 assertions and roughly 36,000 serialized characters per batch), then builds cross-batch candidates from shared reviewed entity IDs, canonical aliases, or exact SKE argument terms. Luna receives the exact original quotes, qualifiers, source versions, regions, and locators for each candidate pair; accepted results remain unresolved contextual syntheses with receipt-bound premise and counterevidence dependencies. The cross-batch candidate limit defaults to 512 pairs and is configurable with `contextPairLimit` (maximum 2,048); exceeding it creates an explicit residual with examined/omitted counts and marks ingestion partial. This bounded linker cannot discover relations between assertions with no shared identity or argument term, so `complete-no-linked-pairs` means the configured linking strategy found no candidates, not that all possible literary or semantic relationships were ruled out.

The separate `resolveSemantics` service in `src/engine/semantic-resolution.mjs` is a bounded goal-directed loop. It interprets a question if no SKE goal was supplied, runs structural matching, retrieves passages within the selected source scope, proposes subgoals/source claims with Luna and sends proposed claims through `reviewAssertions`. Its accepted records are returned as `ephemeralRecords` with review receipts; the caller validates them and may use them in a server-local audit snapshot, but must not persist them as a side effect of answering a question. Its agenda, bindings, residuals, query usage and checkpoint fingerprint are returned to support inspection/resumption.

The pipeline does not convert similarity into entailment, fill a missing premise from background knowledge, or label model review as expert approval. A source quote can support a reviewed semantic assertion only when the separate reviewer accepts the exact SKE, qualifiers and source binding. Coverage gaps and uncertainty remain explicit.
